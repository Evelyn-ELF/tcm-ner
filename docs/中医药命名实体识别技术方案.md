# 中医药命名实体识别技术说明

## 数据与训练

`prepare_data.py` 将字符级 BIO 数据转换为 JSONL，并应用标注修订和样本隔离配置。每条样本包含 `id`、`input` 和 `output`。实体由 `text`、`type`、`start`、`end` 表示，偏移从零开始，结束位置不包含在内。实体必须逐字匹配原文，且同一条标注中不得重叠。数据版本和重建步骤见[标注手册](数据清洗与标注复核手册.md)。

`train.py` 通过 `model_runtime.py` 加载基座和分词器，应用 LoRA 或 QLoRA。训练只对答案和结束标记计算语言建模损失，验证由 `ner_trainer.py` 生成预测并计算实体指标。按验证 Micro-F1 选最佳 checkpoint，导出为 `best_adapter/`。CUDA 训练参数由配置文件和命令行覆盖项决定。

## 输出与计分

当前模板 v4 要求输出 JSON 数组。每个实体包含 `text` 和 `type`。实体文字在原文出现多次时，必须提供从 1 开始的 `occurrence`，按所有精确匹配位置从左到右编号。程序据此生成字符区间。无实体时输出 `[]`。旧适配器通过保存的模板版本和指令保持兼容。缺少序号时，v1、v2 按首次匹配，v3、v4 对重复文字记非法条目。

`evaluate.py` 按类别和完整跨度严格匹配。重复的合法预测只计一次。非法实体条目与未知类别按计分规则计入误报，JSON 解析失败按空预测处理，并单独记录失败率。Micro-F1 按全体实体的命中、误报和漏报计算，Macro-F1 为固定十类 F1 的算术平均。

评估支持加载模型或读取已有预测。离线复算允许换用同 ID、同原文的标注版本。历史提示对照使用 `--validation-experiment`，可选 `baseline`、`boundary`、`recheck`、`principle`。结项模型使用适配器保存的原提示。

## 运行产物

`config.json` 记录实际运行参数，`environment.json` 记录环境和数据文件摘要，`summary.json` 记录训练步数与最佳模型，`validation/step-*/` 保存各验证轮原预测及报告。适配器的 `runtime.json` 保存基座、模板、类别及生成参数。模型和预测文件位于 Git 忽略的 `outputs/`，应从训练机备份。运行命令见[README](../README.md)。
