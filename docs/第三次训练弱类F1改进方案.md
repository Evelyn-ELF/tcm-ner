## 实施顺序

1. **错误归因与标注复核（自动归因完成，标注待裁定）。** 固定第三次模型，在验证集逐类统计漏识别、误识别、边界错误、类别错误、重复文本定位错误和疑似标注错误。保留样本 ID、原文、标注、预测和复核结论。严格匹配下，一处边界错误可能同时产生误报和漏报。
2. **推理对照（已完成）。** 复用项目已有的验证集实验，在同一模型和数据上分别比较原提示、边界提示和弱类补查。检查补查新增的命中与误报，依据验证结果决定是否采用。
3. **数据与采样对照（采样数据已准备，待训练）。** 根据复核结果修订标注，再分别对比新增数据和弱类重采样。首个采样实验可将含中医治则或中医诊断的样本相对采样权重设为约 2 倍，保留其他类别样本。固定基座与其他训练设置，记录采样后的分布。
4. **训练参数对照（待做）。** 数据实验完成后，再分别试验学习率、训练轮数和 LoRA 参数。第三次报告未发现生成截断，输出长度暂列低优先级。

| 类别 | 数据和标注复核重点 |
|---|---|
| 中医治则 | 补充并列治则、治则与治疗方法共现、长句中的治则。验证补查能否提高召回并控制误报。 |
| 中医诊断 | 补充真实语境，增加与临床表现、中医证候、西医诊断容易混淆的对照样本。 |
| 方剂 | 复核漏标、分类一致性以及“加味、加减、自拟”等修饰语的边界，按项目标注规则裁定。 |
| 临床表现 | 优先核查误报，区分多抽取和疑似漏标，补充易混淆样本并统一程度词、否定表达和连续症状的标注规则。 |

每组实验报告总体 Micro-F1、Macro-F1、四类各自的精确率、召回率、F1 和四类平均 F1。当前按验证集 Micro-F1 选择最佳 checkpoint，后续评估选模规则时同时检查弱类收益和总体表现。用验证集做方案选择。若持续依据已查看的测试样本设计改进，另留独立测试集验证泛化。

## 第一步结果与第二步运行方式

使用最佳 checkpoint（第 972 步）保存的 655 条预测，已核对样本 ID、原文和标注与当前验证集逐条一致。下表是按实体位置和类别对齐后的初步归因。完整案例见[验证集错误归因](第三次训练验证集弱类错误归因.json)。

| 类别 | 验证 F1 | 未配对漏识别 | 未配对误识别 | 同类边界错误 |
|---|---:|---:|---:|---:|
| 中医治则 | 54.95% | 23 | 8 | 4 |
| 中医诊断 | 77.97% | 8 | 3 | 1 |
| 方剂 | 67.78% | 26 | 23 | 12 |
| 临床表现 | 75.93% | 62 | 93 | 25 |

上表未列出跨类别错误和非法条目，完整计分以原验证报告为准。治则和中医诊断优先检查漏识别。中医诊断验证集仅有 32 个标注实体，且验证 F1 比测试高 23.13 个百分点，需分开报告两组结果。方剂优先复核修饰语边界（如 dev-000001 的“加味”），临床表现优先复核未配对误报和并列短语拆分（如 dev-000047）。这些样本可用于标注复核，未裁定前保留原标注。

第三次适配器依赖 CUDA QLoRA 和原始基座 `/mnt/Qwen2.5-7B`。当前工作环境缺少该基座和 CUDA。在具备原始基座的训练机上，从项目根目录执行以下对照。

```bash
for mode in baseline boundary recheck; do
  python evaluate.py \
    --adapter outputs/qwen25-qlora-03/best_adapter \
    --data data/processed/dev.jsonl \
    --device cuda --batch-size 16 \
    --validation-experiment "$mode" \
    --output-dir "outputs/qwen25-qlora-03/dev-$mode" || break
done
```

## 第二步结果

三组均使用第三次训练的最佳适配器与同一份验证集。本表以本次重跑的原提示为对照。Macro-F1 由 CSV 中十类 F1 算术平均得到。

| 指标 | 原提示 | 边界提示 | 弱类补查 |
|---|---:|---:|---:|
| 中医治则 | 54.95% | 51.02% | 52.53% |
| 中医诊断 | 71.19% | 72.41% | 71.19% |
| 方剂 | 66.95% | 66.12% | 67.19% |
| 临床表现 | 75.93% | 76.29% | 75.93% |
| 四类平均 | 67.25% | 66.46% | 66.71% |
| Macro | 75.05% | 76.20% | 74.83% |
| Micro | 83.53% | 83.94% | 83.36% |

边界提示使总体 Micro-F1 提高 0.41 个百分点，但治则命中仍为 25 个，误报从 14 增至 21。弱类补查相对原提示多命中 1 个治则和 5 个方剂，同时多出 7 个治则误报和 9 个方剂误报，耗时从约 462 秒增至 931 秒。两种方式的四类平均 F1 均低于原提示。下一轮暂用原提示，先复核治则与诊断漏识别、方剂边界和临床表现误报，再为数据和采样实验准备样本。

产物位于 `outputs/qwen25-qlora-03/dev-baseline`、`dev-boundary` 和 `dev-recheck`，各目录的 `validation_metrics.csv` 和 `experiment.json` 分别记录指标和耗时。

## 第三步准备

以推理对照重跑的原提示结果为准，整理[弱类漏识别复核清单](弱类漏识别复核清单.json)。按严格匹配统计，治则漏报 27 个，其中 6 个在训练集没有同类同词标注，8 个存在重叠预测。中医诊断漏报 11 个，全部在训练集中有同类同词标注，4 个存在重叠预测。两项计数可以重叠，重叠预测需逐条判断。

治则补样优先覆盖并列短语、治则与药物共现及长短边界。诊断优先补充同词异义的语境对照，例如病名“积聚”和“积聚腹腔”中的动词用法，具体标签仍按规范复核。不将清单中的验证句加入训练集。

训练集共 5170 条，其中 320 条包含治则或中医诊断。首个采样实验计划让这 320 条每轮多出现一次，双类共现的句子也只额外计一次。每轮共 5490 条。原始数据和验证集继续作为对照。记录实际训练步数，因为增加采样会同时增加每轮训练步数。采样实验尚未运行。

采样数据和配置已生成至 `data/processed-weak-resample`。训练文件通过样本校验，320 条额外样本使用独立 ID，验证与测试文件经逐字节比对一致。配置以第三次的实际运行配置为准，仅修改数据路径。本次先验证采样本身，标注裁定和补样另行对照。将该目录同步到 CUDA 训练机后运行。

```bash
python train.py --config data/processed-weak-resample/train-config.json \
  --run-name qwen25-qlora-04-weak-resample
```

训练后用第二步的原提示命令评估新适配器，输出至新实验目录，和第三次重跑的原提示结果比较四类平均 F1 与总体 Micro-F1。
