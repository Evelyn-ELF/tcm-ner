# 中医药命名实体识别技术方案

本文说明当前代码的设计与行为。运行命令见 [README](../README.md)，实测结果见[开发验证记录](开发验证记录.md)。

## 1. 整体流程与模块

项目采用 Qwen2.5-7B 基座模型，通过 QLoRA 学习从原文生成实体 JSON 数组。普通 LoRA 是可选配置。流程如下：

```text
BIO 数据 → 字符与标注校验 → 清洗训练集 → SFT JSONL
        → 答案区监督训练 → 验证集生成与模型选择 → 最佳 adapter
        → 测试集评估 / 新文本预测
```

训练循环与 checkpoint 管理由 Transformers 提供，LoRA 由 PEFT 提供，4-bit 量化由 bitsandbytes 提供。项目只支持单进程、单设备。

| 模块 | 主要职责 | 项目内依赖 |
|---|---|---|
| [ner_types.py](../ner_types.py) | 实体、样本、预测和指标类型 | 无 |
| [ner_utils.py](../ner_utils.py) | 数据读取、校验、提示、解析与计分 | `ner_types` |
| [prepare_data.py](../prepare_data.py) | 清洗训练集、统计和审计 | `ner_types`、`ner_utils` |
| [model_runtime.py](../model_runtime.py) | 编码、模型加载、LoRA、生成和重载 | `ner_types`、`ner_utils` |
| [ner_trainer.py](../ner_trainer.py) | 向 Trainer 验证结果加入实体指标 | `ner_types`、`ner_utils`、`model_runtime` |
| [train.py](../train.py) | 编排训练、监控和保存 | 上述类型、工具与训练模块 |
| [evaluate.py](../evaluate.py) | 生成评估、离线重评及可选 TensorBoard 指标记录 | `ner_types`、`ner_utils`；生成时加载 `model_runtime` |
| [predict.py](../predict.py) | 单段文本预测 | 按需加载 `model_runtime` |

数据读取和计分不依赖深度学习框架。`run_training()` 通过私有函数分别完成配置校验、数据准备、长度检查、环境记录、监控、Trainer 构建和产物保存。

## 2. 数据处理与结构

### BIO 转换和清洗

原始数据每行一个字符及 BIO 标签，空行分隔样本。读取时只去除行结束符，保留全角空格、标点等原文字符。

`B-X` 和后续同类 `I-X` 合并成实体；遇到 `O`、新的 `B` 或句末时结束。未知标签、非法衔接和错误行格式直接报错，不自动修补。

训练数据按以下优先级排除，并记录原因：

1. 原文与验证集或测试集重合：排除全部对应训练记录。
2. 同一原文有不同标注：整组隔离。
3. 原文和标注完全重复：保留第一条。

保留样本维持原始顺序和 ID。验证集、测试集保留原标注，重复和冲突写入审计。三个原始集合及清洗后的训练集均不能为空。

### 样本与实体

类别固定为：中药、方剂、临床表现、中医证候、中医诊断、西医诊断、中医治则、中医治疗、西医治疗、其他治疗。`O` 不是实体类别。

JSONL 每行一个对象，使用 UTF-8。下面是一个可用的标注样本；省略 `instruction` 时，提示构造函数使用项目固定指令：

```json
{"id":"示例-1","input":"患者口苦","output":[{"text":"口苦","type":"临床表现","start":2,"end":4}]}
```

位置采用 Python 字符索引，左闭右开：`input[start:end] == text`。不能混用 token 或字节位置，布尔值也不能用作整数位置。

数据类型定义在 [ner_types.py](../ner_types.py)：

| 类型 | 内容及可选项 |
|---|---|
| `Entity` | `text`、`type`、`start`、`end` |
| `InputSample` | 必需 `id/input`，可选 `instruction` |
| `Sample` | 在 `InputSample` 上增加必需的 `output: list[Entity]` |
| `EncodedSample` | 等长的 `input_ids/attention_mask/labels` 列表 |
| `ParsedPrediction` | 合法实体、解析错误、按类别统计的非法项、未知类别 FP 和条目错误 |
| `Prediction` | 输入字段与原始输出、解析实体、错误、生成上限标志；`output` 可选 |
| `ItemError` | 非法条目的 `index/reason` |
| `EntityMetrics` | `precision/recall/f1/support/tp/fp/fn` |
| `MetricsReport` | 逐类及总体指标、异常统计；补充报告可含 `excluded_overlap_samples` |

这些 TypedDict 描述字段，不替代运行时校验。`read_jsonl()` 只检查每行是否为 JSON 对象；`validate_samples()` 再检查 ID 唯一性、字段结构和实体合法性。

转换程序会写入完整固定指令；显式提供其他指令时，`build_prompt()` 拒绝执行。无实体标注使用 `[]`。BIO 转换按原文顺序产生实体，训练编码保留输入数组的顺序；预测解析后才明确按 `(start, end, type)` 排序。

## 3. 编码与训练

### 提示和监督范围

训练与推理共用 `build_prompt()`：

```text
任务：{固定指令}
文本：{input}
答案：
```

训练时在提示后拼接紧凑 JSON 答案及 EOS。提示和答案分别分词，均设置 `add_special_tokens=False`；答案使用 `ensure_ascii=False, separators=(",", ":")` 序列化。

只有答案和真实 EOS 参与损失，提示与 padding 的标签为 `-100`。批次补齐由 `DataCollatorForSeq2Seq` 完成。tokenizer 缺少 pad token 时复用第一个 EOS；即使两者 ID 相同，也根据位置屏蔽 padding，保留真实 EOS 的监督。

### 长度与模型准备

**token 长度检查发生在训练入口加载 tokenizer 之后，`prepare_data.py` 不做分词检查。** 对训练和验证数据，必须同时满足：

```text
完整序列长度 <= min(training.max_length, 模型上下文上限)
答案长度（含 EOS） <= generation.max_new_tokens
提示长度 + generation.max_new_tokens <= min(training.max_length, 模型上下文上限)
```

超长时直接报错，不截断答案。推理也检查“提示＋生成预算”是否超过上下文。

QLoRA 使用 NF4 和双重量化，先执行 `prepare_model_for_kbit_training()`，再注入 LoRA。默认启用梯度检查点，训练时关闭 KV cache。精度为 `auto` 时，CUDA 优先 BF16，否则 FP16；CPU 使用 FP32。

### 验证和最佳模型

每个 epoch 先按 `training.eval_batch_size` 分批计算验证损失，再按 `generation.batch_size` 分批自主生成验证答案。生成输入只包含提示和原文，不包含真实标签。

`EntityTrainer.evaluation_loop()` 保存预测与报告，并将 `eval_entity_micro_f1` 加入返回指标。Trainer 据此选择最佳 checkpoint，同分保留较早者；训练结束后加载并保存最佳 adapter。

TensorBoard 在本地记录训练与验证聚合指标。配置、数据哈希和依赖信息保存在 `environment.json`。训练日志每 10 个优化器步记录一次，首步也记录。

## 4. 生成、解析与评估

### 生成和解析

生成使用 `model.eval()`、`torch.inference_mode()` 和 `do_sample=False`，对同批提示做左填充并传入注意力掩码。按输入顺序保存预测，解码时只保留生成部分中首个 EOS 之前的内容。结束或异常时恢复模型原有模式和分词器的填充方向。若输出用尽生成预算且没有 EOS，记录 `hit_generation_limit=true`。

解析规则如下：

- 输出必须是 JSON 数组，不提取 Markdown 代码块，也不修补损坏 JSON。
- 实体必须有合法类别、有效非空边界，且文字与原文切片一致。
- 相同类别及位置的合法预测去重，同词不同位置分别保留。
- 整体解析失败按空预测处理，真实实体全部计为漏检，样本不丢弃。
- 数组内非法条目额外计一次 FP；未知类别计入总体 FP，不计入任何已知类别。

### 指标口径

类别、起点、终点都相同才算正确实体。例如，“慢性胃炎”被预测为“胃炎”，计一次 FP 和一次 FN。

```text
TP = 正确匹配的实体数
FP = 未匹配预测数 + 非法条目数
FN = 未匹配真实实体数
Precision = TP / (TP + FP)
Recall = TP / (TP + FN)
F1 = 2TP / (2TP + FP + FN)
```

Micro-F1 汇总全语料的 TP/FP/FN 后计算；Macro-F1 对固定 10 类 F1 求平均。零分母按零处理，`support=TP+FN`。非法条目额外计 FP 是本项目的补充约定，与外部实验比较前需对齐口径。

报告还包含 JSON 解析失败率、非法条目数、未知类别 FP 和生成上限命中率。无实体样本也进入异常率统计。

### 评估入口的约束

`evaluate.py` 要求 `--adapter` 与 `--predictions` 二选一。加载 adapter 生成时，`--batch-size` 默认是 4。离线重评从 `raw_output` 重新解析，不信任缓存的解析结果。

指定 `--data` 时，两份文件都需有合法标注样本，且 ID 集合完全一致；计分使用 `--data` 的原文和标注。当前不校验同 ID 的原文是否一致，调用方需保证数据版本匹配。

验证重合的补充报告优先使用 `--dev-data`，否则 adapter 模式读取 `validation_texts.json`；没有验证原文来源时只生成主报告。主评估拒绝空集合，排除重合后的空集合则输出零指标。

最终测试使用最佳 adapter，测试结果不参与模型选择。

## 5. 配置和异常行为

配置源为 [configs/train.yaml](../configs/train.yaml)，顶层包含 `model/data/training/lora/generation/tensorboard`。以下是当前主要值，完整字段以配置文件为准：

| 项目 | 默认值 |
|---|---|
| 模型 / revision / 方法 | `/mnt/Qwen2.5-7B` / `main` / `qlora` |
| 精度 / 设备 | `auto` / `cuda` |
| 训练轮数 / batch / 梯度累积 | `3` / `4` / `4` |
| 验证损失批大小 / 验证生成批大小 | `4` / `4` |
| 学习率 / warmup / 调度 | `0.0002` / `0.03` / cosine |
| LoRA r / alpha / dropout | `16` / `32` / `0.05` |
| LoRA 目标层 | `q_proj`、`k_proj`、`v_proj`、`o_proj`、`gate_proj`、`up_proj`、`down_proj` |
| 总长度 / 生成预算 | `2048` / `1536` |
| 随机种子 / TensorBoard 开关 | `42` / `true` |

模型加载通过 Transformers 的 `dtype` 参数传入由 `model.precision` 和设备解析得到的精度。

旧配置省略 `training.eval_batch_size` 或 `generation.batch_size` 时，对应批大小为 1。`--batch-size`、`--gradient-accumulation-steps`、`--generation-batch-size`、`--max-steps`、`--tensorboard/--no-tensorboard` 覆盖对应 YAML 值；`--train-limit/--eval-limit` 校验完整数据后取前 N 条，仅影响本次运行。

CUDA 模式要求仅一张可见 GPU，且 `WORLD_SIZE=1`。CPU 不支持 QLoRA，仅支持 FP32 LoRA。模型、设备或文件错误向上抛出，不自动换模型、设备或监控模式。

所有相对路径以当前工作目录为准。训练目录禁止覆盖；数据和评估的同名文件允许覆盖。文件写入不提供事务回滚，失败后可能留下部分产物，不能只凭目录存在判断成功。

## 6. 产物约定

产物位置见 [README](../README.md)。需要跨模块使用的文件内容如下：

| 文件 | 主要内容 |
|---|---|
| `data_audit.json` | 处理规则和模板版本、源数据哈希、清洗前后统计、排除记录、标注冲突、验证/测试重合原文 |
| `config.json` | 命令行覆盖后的有效配置 |
| `environment.json` | 环境、依赖、数据哈希、长度统计、样本限制、有效 batch 和模型 revision |
| `summary.json` | 最佳验证 F1、checkpoint、adapter 路径、结束步数、训练指标、TensorBoard 日志目录、贯通检查标志 |
| `best_adapter/runtime.json` | 模板版本、指令、类别、模型来源、生成预算、总长度和 EOS |
| `best_adapter/validation_texts.json` | 实际参与验证的原文去重列表 |

adapter 重载时校验模板、指令及类别清单。远程基座保存解析到的 revision；本地基座保存绝对路径。adapter 不包含完整基座权重。

模型生成的预测文件使用 `Prediction` 结构；离线重评只要求 `id/input/output/raw_output`，可带 `hit_generation_limit`。指标 JSON 对应 `MetricsReport`，保留原始精度。CSV 使用 UTF-8 BOM，列为 `类别,precision,recall,f1,support,tp,fp,fn`，包含 10 类和 Micro 行；Macro-F1 与异常统计保存在 JSON 并打印到控制台。
