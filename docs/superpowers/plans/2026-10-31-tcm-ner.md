# 中医药 NER 实施与验收计划

> 历史实施计划：代码与 CPU 贯通阶段已完成，目标 GPU 验收仍待执行。本文保留当时实施过程，不作为当前操作指南。当前使用说明见 [README](../../../README.md)，结果见[开发验证记录](../../开发验证记录.md)。

本计划覆盖数据处理、模型微调、实体评估和运行验证。技术设计见 [中医药命名实体识别技术方案](../../中医药命名实体识别技术方案.md)，运行命令见项目 README。

## 实现原则

模型采用 `Qwen/Qwen2.5-7B`，默认使用单卡 QLoRA。评价要求实体类别和完整边界同时匹配，并输出固定 10 类实体的指标。训练数据保留原文字符，清洗过程隔离标注冲突并排除与评估集重合的文本。

通用训练能力由 Transformers 和 PEFT 提供。W&B 记录配置及聚合指标，逐条预测和评估报告保存在本地。CPU 微型模型用于验证流程，正式微调使用 NVIDIA CUDA 环境。

## 1. 数据处理与实体计分

`prepare_data.py` 负责转换和审计，`ner_utils.py` 提供共用的数据读取、提示模板、输出解析和计分函数。

`read_bio(path, split)` 将逐字 BIO 合并为带位置的实体；`prepare_data(data_dir, output_dir)` 输出 SFT JSONL 与审计报告；`parse_prediction(text, raw)` 解析生成结果；`score_predictions(records)` 汇总逐类和总体指标。

验收覆盖全角空格保留、非法 BIO、标注冲突、跨集合重合、样本 ID 唯一性、同词不同位置、错误 JSON 和非法实体条目。相关测试位于 `tests/test_data_metrics.py` 和 `tests/test_evaluate_cli.py`。

## 2. 编码与模型运行

`model_runtime.py` 负责样本编码、基座加载、LoRA 注入、确定性生成和 adapter 重载。参数统一存放在 `configs/train.yaml`。

`encode_sample(sample, tokenizer, eos_id, max_length)` 构造输入和答案监督标签。`train.py` 使用 Transformers 的 `DataCollatorForSeq2Seq` 补齐批次。`generate_records()` 仅编码提示与原文，返回原始生成内容、实体及解析状态。

验收要求提示和 padding 不参与损失，答案 EOS 保留监督，超长输入明确报错。推理输入不含真实答案，模型运行限制为单进程单设备。编码测试位于 `tests/test_encoding.py`。

## 3. 训练、评估与监控

`train.py` 组织训练和 W&B 监控，`ner_trainer.py` 接入生成式验证，`evaluate.py` 执行测试集评估或已有预测重新计分，`predict.py` 处理新文本。

`EntityTrainer.evaluation_loop()` 在返回前加入 `eval_entity_micro_f1` 并保存验证结果，父类 `evaluate()` 继续处理日志和回调。Trainer 根据验证实体 Micro-F1 选择最佳 checkpoint，训练结束后保存最佳 adapter、tokenizer 和运行元数据。

验收包括微型 Qwen2 的 LoRA 单步训练、W&B 离线日志、最佳 adapter 保存，以及独立进程中的评估和预测。相关测试位于 `tests/test_training.py`。

## 4. 运行验收

代码及 CPU 微型模型贯通测试已完成，验证结果见 [开发验证记录](../../开发验证记录.md)。README 提供安装、数据处理、训练、评估和预测命令。

目标 GPU 验收需要确认完整 Qwen2.5-7B 的量化加载、显存占用、短训练和 adapter 重载。完成后执行正式训练，并使用最佳 adapter 对完整测试集评估一次，保存逐类 F1、总体指标及预测文件。测试集结果不参与模型选择。
